# approved_reports/

Отчёты, утверждённые пользователем кнопкой **«✅ Нормальный ответ»** в UI.

Каждый файл — JSON одного утверждённого прогона:

```json
{
  "id": "approved-2026-05-20-abc12345",
  "approved_at": "2026-05-20T15:30:00Z",
  "input": "<исходный текст креатива>",
  "drug_class": "OTC",
  "violations": [...],
  "rewritten_text": "<compliant-вариант>",
  "user_feedback_history": [
    "первый комментарий пользователя",
    "второй комментарий"
  ],
  "iterations": 3
}
```

## Зачем

1. **Внутренняя база знаний бренд-команды.** Утверждённые прогоны фиксируют, какие
   формулировки команда считает приемлемыми, и какие комментарии помогали
   доводить до compliant-варианта. Эта папка — единственный источник истины
   о решениях бренда (в отличие от `fas_decisions/`, где лежат внешние ФАС-решения).
2. **Постепенная разметка для regression-eval.** Утверждённые случаи можно
   конвертировать в записи `regression_dataset/` через `compliance ingest`
   (запланировано в следующих итерациях).
3. **Аудит.** Полная история комментариев пользователя сохраняется в
   `user_feedback_history` — видно, какими указаниями пользователь привёл агента
   к итоговому ответу.

## Что НЕ хранить

- PII (ФИО реальных людей, упомянутых в креативах) — очищать перед approve.
- Закрытые регуляторные согласования с юристом — это отдельный документооборот.
- Креативы конкурентов — для них есть `fas_decisions/`.
